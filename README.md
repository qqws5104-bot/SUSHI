# 회전초밥 벨트 (시험판)

택배 게임의 엘리베이터 단계를 "끝이 없는 회전초밥 벨트"로 바꾼 규칙 시험판입니다 (2026-10-08, 새 사이트로 가기 전 단계).
`belt_proto.html` 하나를 브라우저에서 열면 됩니다 (서버 불필요).

## 규칙 (기본값: 색 모드)
세계관: 택배 확보 = 초밥 만들기, 엘리베이터 = 색색의 접시가 도는 벨트, 목적지 층 = 접시 색, 택배 4종 = 주문 4종. (STEP 1 미니게임은 이 시험판에 없고, 주문마다 종류가 무작위로 붙습니다.)
- 벨트에는 접시 10장이 한 바퀴를 돕니다. 색 10가지(빨강 주황 노랑 초록 파랑 보라 분홍 흰색 검정 회색)가 한 장씩, 그리고 무늬 5종(물방울 줄무늬 별 하트 체크)이 각각 두 장씩 그려져 있습니다. 색과 무늬는 독립이라 색만으로 구분하지 않아도 됩니다.
- **먹는 칸은 아래쪽 한 곳뿐이고 두 사람이 같이 씁니다** (엘리베이터처럼). 라운드마다 각자 비밀 주문 하나를 받습니다.
- **주문표 = "무슨 초밥을 만들어서, 어느 접시에 올려라".** (원래 택배의 종류가 만들 초밥의 급이 되고, 원래 송장의 층이 올릴 접시가 됩니다.) 주문 종류는 원래 택배 비율 4:6:4:3으로 나옵니다.
  - 일반(2점): 계란·유부 같은 쉬운 초밥. 두 색 중 **아무 접시나** 인정.
  - 지정(3점): 새우·문어. 지정된 **색 한 가지**, 또는 **무늬 한 가지**(같은 무늬 두 장 중 어느 쪽이든). 색/무늬는 반반.
  - 중급(5점): 연어·연어알. **정확히 한 색**에 올라가야 인정.
  - 특선(10점): 장어·참치. **정확히 한 색**에 올라가야 인정.
  - 초밥은 급마다 두 가지 중 무작위. 점수는 원래 보상금(2500/3000/5000/10000)을 비율대로 반올림한 값이고, 실패 페널티는 이 시험판에 없습니다. 실제 게임에서는 STEP 1 미니게임으로 이 초밥을 "만든" 것이 되고, 여기서는 주문마다 무작위로 붙습니다.
- 끝났을 때 먹는 칸의 접시 위에 두 사람이 만든 초밥이 올라가고(틀리면 흐리게 X), 접시가 내 주문표의 규칙에 맞으면 그 주문의 점수. 두 주문이 같은 접시를 받아 주면 둘 다, 한쪽만이면 그쪽만, 둘 다 아니면 아무도 못 받습니다.
- 주문 배정: 30% 확률로 "한 접시를 둘 다 받아 주는" 쌍을 줍니다 (본인들은 모름). 나머지는 무작위.
- 브레이크(벽이 없어서 필요): 하프(7라운드) 전체에서 한 사람이 밀 수 있는 횟수 48회.
- 막판 매복 방지: 실제 종료는 5초 ±1초 사이 무작위, 화면 시계는 가장 이른 종료(4초)까지만 세고 그 뒤는 "!".
- 라운드는 약 5초. 그동안 두 사람이 벨트를 시계/반시계로 한 칸씩 밉니다. 누른 즉시 움직이고 서로의 접시가 같이 돌아갑니다.
- 키: 컴퓨터와 할 때 ← → 또는 A D. 둘이서 한 화면이면 1P = A D, 2P = ← →. 꾹 누르기는 안 먹습니다. Space = 시작/다음, R = 새 판.

설정 패널에서 바꿔 볼 수 있습니다: 접시 구성(색 10가지 = 기본 / 맛 8종 12칸 = 이전 방식), 자리 규칙(한 칸 공유 = 기본 / 각자 자리 2개), 브레이크(총량 / 라운드 이동 범위 / 제한 없음), 총량, 맞물리는 주문 비율, 라운드 시간, 종료 흔들림, 봇 연타 속도, 소리.
URL로도 됩니다: `?plates=color&mode=two&seatRule=any&brake=cap&cap=4&budget=48&coop=30&roundMs=5000&jitter=1&rounds=7&botRate=3&seed=1&sound=0` (`plates=sushi`가 이전 12칸 8종).

## 파일
- `belt-core.js` -- 규칙 전부 (시간/난수를 받는 순수 모듈, 브라우저·node 공용). 봇(`makeBot`)도 여기.
- `belt-ui.js`, `belt.css`, `belt_page.html` -- 화면. `python3 build.py`가 `belt_proto.html` 하나로 합친다.
- `test_core.js` (규칙 + 봇 시뮬레이션), `test_ui.js`, `test_ui_jitter.js` (Playwright). `sim_color.js` (색 10종 vs 6종 비교), `shot*.js` 스크린샷 도우미.

## 시뮬레이션으로 알게 된 것 (봇 기준 -- 사람은 다를 수 있음)
1. **종류만 늘리면 협력이 줄고 멀어진다.** 접시 배치를 무작위로 바꿔 계산하면, 6칸 6종(맛 1개씩)은 둘이 동시에 맞출 수 있는 주문 쌍이 17%, 12칸 8종은 18%이면서 내 주문까지 평균 밀기가 1.5칸 -> 2.4칸으로 늘어납니다. 같은 맛이 두 번 나오는 배치(12칸 6종x2: 30%, 10칸 5종x2: 35%)가 협력에는 더 좋았습니다. 사용자가 12칸 8종을 선택해서, 그대로 두고 **주문 배정(coopDeal)** 으로 보정했습니다: 30%는 항상 동시에 맞출 길이 있는 쌍을 줘서 동시 만족 가능 비율이 15% -> 약 41%. 봇끼리 7라운드에서 둘 다 먹은 라운드가 0.95회 -> 2.6회.
2. **막판에 몰아 미는 쪽이 이긴다.** 마지막 0.7초에만 초당 8회로 미는 봇이 평범한 봇을 7라운드에 평균 약 8점 차로 이겼습니다 (총량 제한이 있어도). 종료 시각을 ±1초 숨기면 약 4.5점으로 줄지만 없어지지는 않습니다. 둘 다 이걸 알면 4초 동안 아무도 안 밀다가 마지막에 몰리는 게임이 될 가능성이 있고, 이건 사람이 해 봐야 압니다.
3. **브레이크가 없으면 연타 속도가 결과를 좌우한다.** 제한 없음에서 연타가 2배인 쪽이 평균 +7~8점. 총량 제한/이동 범위 제한은 이걸 줄입니다.
4. 12칸에서는 내 주문이 평균 2.4칸 떨어져 있어, 총량 48회는 봇끼리 거의 다 쓰는 수준(45~48회)입니다. 사람이 해 보고 모자라거나 남으면 조정하세요.

5. **한 칸 공유로 바꾼 뒤 (봇, 300판, 12칸 8종, 판당 평균 라운드 수 / 7):** coopDeal 0이면 둘 다 먹음 0.83 / 한쪽만 3.95 / 아무도 2.23, 30%면 2.62 / 2.78 / 1.59. 각자 자리 방식과 거의 같은 숫자입니다. 다만 주문이 서로 다른 라운드는 한 칸을 두고 줄다리기가 되고, 아무도 못 먹는 라운드가 여전히 판의 20% 이상입니다. 개선 후보: 라운드마다 주문 2~3개를 손패로 주고 하나라도 맞으면 득점.

6. **색 10가지로 간 경우 (사용자 지정, 봇 300판, 한 칸 공유):** 10색을 한 장씩 두고 주문이 "한 색"뿐이면 아무도 못 먹는 라운드가 1.91회로, 6색 x 2장(1.37회)보다 0.5회 늘었습니다(coopDeal 0.3). 주문 종류를 넣어 일반(두 색)과 무늬 지정(두 장)이 허용 접시를 늘려 주니 1.49회로 줄었고, 둘 다 먹은 라운드는 2.38회입니다. 즉 10색의 대가는 컸지만 주문 종류 규칙이 대부분 메워 줍니다. 단, 이 숫자는 주문 종류가 4:6:4:3으로 섞일 때 얘기입니다.
7. 한 칸을 공유하면 coopDeal "맞물림"은 사실상 "둘이 같은 접시를 원하는 라운드"라서, 비율을 올릴수록 갈등이 줄고 줄다리기가 약해집니다. 0.3 이상은 올리지 않는 걸 권합니다.
